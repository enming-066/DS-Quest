## 一、先说我现在的真实状态

我是大二，C++ 很差。不是"不太熟"，是**真不会**：

- `int *p` 和 `int &r` 我能背出"指针存地址、引用是别名"，但**看到代码里出现 `&` 就分不清是取地址还是引用**；
- `p->next` 和 `p.next` 我每次都要犹豫，`new` 出来的东西到底在哪儿、什么时候没的，我一点概念都没有；
- 类、构造、析构、`template<class T>`、`friend`、`operator[]`——老师 PPT 里满屏都是，网课里一个都没讲。

我学过的东西来自 B 站逊哥（他用 C），所以我**原理是懂的**：栈是后进先出、循环队列要取模、链表插入要改指针。
但一到我们老师的 PPT，我就懵，因为：

1. 代码从 `SqList` 变成了 `ArrayLinearList<T>`，还多了 `T* element; int arrayLength; int listSize;`；
2. 插入从"第 i 个位置"变成了"下标 theIndex"，还带一个 `changeLength1D` 扩容；
3. 链表不带头结点了，`firstNode` 直接指首元，删除还要单独判 `theIndex == 0`；
4. 好端端的 `printf` 变成了 `throw OutOfBounds();`。

**所以我的问题不是"数据结构没学会"，而是"我看不懂我们老师的那套代码"。**

### 我试过什么，为什么没用

| 我试过 | 结果 |
| --- | --- |
| 看老师 PPT | 一页 40 行模板代码，没有任何一行告诉我 `T` 是什么、`&` 是什么 |
| 看逊哥的网课 | 原理懂了，但他写 `InitList(&L)`，老师写 `ArrayLinearList(int initialCapacity=10)`，对不上 |

### 一句话总结我的需求

> **我要的不是更多题，是"看得懂的代码"、"对得上的术语"和"敢下手的练习"。**

## 二、所以这个工具应该解决的五件事

### 1. 让 C++ 语法不再挡路（不是学 C++，是学"数据结构里出现的这点 C++"）

我不需要系统学 C++，我只需要搞懂**这 12 个东西**：

```cpp
T / template<class T>     // 泛型：把 int 换成 T 而已
T* p                      // 指针：p 存的是地址
p->next  vs  p.next       // 指针用 ->，对象用 .
int& r  vs  &x            // 左边是引用，右边是取地址
new / delete              // 手动申请、手动释放
构造函数 / 析构函数         // 建对象时跑 / 销毁时跑
类里的 private / public    // 能不能从外面访问
T** table                 // 指针的数组（间接寻址用）
throw / try / catch       // 出错就抛，外面接住
const 成员函数             // 这个函数不改对象
NULL / 0 / nullptr        // 空指针
static / 友元 friend       // 谁能访问私有成员
```

**做法**：做一套「C++ 路标」——每个语法点配一个 30 秒的微课（用数据结构里的真实代码当例子，不用"动物会叫"那种例子），并且在每份代码模板上方自动列出"读这段代码你需要先知道哪 3 个语法点"。

### 2. 把"老师的 C++"和"逊哥的 C"并排放

我脑子里的锚点是逊哥的 C 版。工具应该让我**用已有认知去挂新知识**：

```
逊哥（C）                        老师（C++）
struct SqList {                  template<class T>
    int data[MAXSIZE];           class ArrayLinearList {
    int length;                      T* element;
};                                   int arrayLength, listSize;
                                 };
```

同一段算法，左边 C、右边 C++，**差异处高亮 + 一句话解释"为什么这里要这么写"**。
看懂差异，我就不用重新学一遍原理。

### 3. 术语要能互相翻译

同一个东西，三套叫法，我每次都要在脑子里转译：

| 概念 | 逊哥（C） | 老师 PPT（Sahni/C++） | 差异 |
| --- | --- | --- | --- |
| 顺序表 | `SqList`、`length` | `ArrayLinearList<T>`、`listSize` | 名字不同，含义一样 |
| 插入 | `ListInsert(&L, i, e)`，位序 i | `insert(theIndex, x)`，下标 | **差 1** |
| 链表 | 带头结点 `L->next` | 不带头结点 `firstNode` | **判空/删首元写法不同** |
| 循环队列 | `front` 指队头元素 | `front` 指队首前一位 | **判满公式相反** |
| KMP next | `next[1]=0` | `next[0]=-1` | **数组整体偏移** |
| 栈 | `top` 指栈顶 | `stackTop = -1` | 一致 |

**做法**：做一张可搜索的「术语罗盘」，并且**在我可能踩坑的地方主动弹提示**（比如看我做到循环队列的题，就提示"注意老师的 front 约定和逊哥不一样"）。

### 4. 练习要从"读"开始，不能一上来让我写

我现在打开判题就是一片空白，这跟让我抄课文前先默写一样。

正确的阶梯应该是：

```
① 读：看一段带逐行解释的代码，跟着走一遍
② 推：给定操作序列，我在图上点出每一步的结果（猜完再看动画）
③ 填：代码挖 3~5 个空（通常是关键指针操作），我补全，系统真跑测试
④ 改：给一段有小错的代码（断链、少 delete、边界差一），我找出来修好
⑤ 写：这时才给空白编辑器
```

**关键是 ③ 和 ④ 也要能判题**——不是"看看答案对不对"，而是真的编译运行跑测试用例。
技术上完全可行：把挖空代码拼成完整程序再交给现有的判题引擎。

### 5. 让"我写的代码"和"动画"对上

现在的可视化是"我点按钮，它演给我看"，跟我的代码没关系。
我真正需要的是：**我写的这段代码，跑起来的时候内存里发生了什么**。

- 指针指向哪、什么时候断链、什么时候变野指针；
- `new` 出来的结点在堆上，`firstNode` 在栈上；
- 递归时调用栈一层层压下去、再弹回来。

**做法**：做一个「内存视图」——左边是我的代码，右边是栈区/堆区的盒子图，点某一行就高亮那条语句产生的变化。

## 三、内容层要怎么改（不改架构，只加"阅读层"）

现有内容最大的问题：**默认读者已经会 C++**。所以我给每个知识点/模板都加一层"阅读辅助"，不改算法讲解本身。

### 3.1 知识点：开头加「零基础导航」

每篇开头加三行：

```
这篇你会用到：指针（* 和 ->）、类（class 和 public）、new/delete
没学过？先看 👉 C++ 路标 ③ 指针
读完你应该能：自己写出 insert 的循环方向
```

### 3.2 代码模板：加「逐行拆解」模式

现在是"逐段解释"（讲算法），要加一个"逐行"（讲语法）：

```cpp
1  template<class T>                      ← T 是类型占位符，相当于"先不写 int"
2  class ArrayLinearList {                ← class 定义一个"类型"，里面可以装数据和函数
3  public:                                ← 下面这些外面可以访问
4      ArrayLinearList(int cap = 10) {    ← 构造函数：new 这个类时自动执行
5          element = new T[cap];          ← 在堆上申请 cap 个 T，element 指向它
```

点任意一行 → 右侧显示：**这行在干什么 / 用到的语法 / 内存里发生了什么 / 对应的 C 写法**。

### 3.3 每章结尾加「术语对照 + 差异警告」

比如第 2 章结尾明确写：

> ⚠️ 循环队列：逊哥课上 `front` 指队头、老师 `front` 指队首前一位，**判满公式刚好相反**。考试按老师的写。

### 3.4 题目：分「读→推→填→改→写」五档

现有 26 道题全部保留，但重新打标签，并且给每道主线题补一个"填空版"（同一个考点，降低下手难度）。

## 四、学习路径（从"我现在学到队列"往后排）

我现在的位置：学完线性表、栈，正在学队列。所以路径不是从第 0 章重来。

### 第 0 周（2~3 小时）：C++ 急救

只学 12 个语法点里的前 6 个（`template`、指针、`->`、`new/delete`、构造/析构、`public`），
全部用**我已经学过的顺序表/链表/栈**当例子——不引入新知识，只换"语言"。

**验收**：能指着 `Chain<int> c; c.insert(0, 5);` 说出每一部分在干什么。

### 第 1 周：把已学的三章"过一遍代码"

不是重学原理，是**把逊哥的 C 版和老师的 C++ 版对上**：
顺序表 → 链表 → 栈 → 队列，每章做 3 件事：读一遍逐行版 → 做 2 道填空 → 做 1 道改错。

**验收**：能独立默写出 `insert` 和 `erase`（允许查语法，不允许查思路）。

### 第 2 周：跟课学队列 + 开始写

队列这一章按"读 → 推 → 填 → 改 → 写"走完：
- 循环队列的判满（注意 front 约定）
- 链队列的删除特判
- 约瑟夫环（循环链表）

**验收**：在没有 starterCode 的情况下，独立写出循环队列的 `enqueue/dequeue` 并通过判题。

### 第 3 周起：按课程进度走

每学一章，先看"这一章在网课里对应哪一节"（我已经整理好了映射），再用工具补 C++ 代码。
不再超前做没学过的章节。

## 五、具体要做的六个模块（按优先级）

| 优先级 | 模块 | 一句话 | 依赖 |
| --- | --- | --- | --- |
| P0 | **C++ 路标** | 12 个语法点的 30 秒微课 + 在代码里自动标注 | 无 |
| P0 | **逐行拆解器** | 点代码任意一行，讲这行的语法/内存/等价 C 写法 | 无 |
| P0 | **术语罗盘** | C / 严蔚敏 / 本校 PPT 三列对照，踩坑处主动提示 | 无 |
| P1 | **填空判题** | 把模板挖空，用户补全，真编译真跑测试 | 复用现有 judge |
| P1 | **改错判题** | 给带 bug 的代码，用户改对才能过 | 复用现有 judge |
| P2 | **内存视图** | 代码行 ↔ 栈/堆盒子图联动 | 需要轻量解释器或可视化规则 |
| P2 | **先猜后看的手推** | 给定操作序列，先点出结果再看动画 | 复用现有可视化组件 |

### 每个模块的验收标准

- **C++ 路标**：12 个点，每个 ≤ 60 秒读完，例子全部来自数据结构的真实代码；能从代码块一键跳到对应语法点。
- **逐行拆解器**：任意一份现有模板，每一行都有解释；"等价 C 写法"覆盖至少 80% 的行。
- **术语罗盘**：至少 20 组术语对照；在对应题目页自动出现差异提示。
- **填空判题**：每道主线题有一个填空版；判题结果与完整题一致（真跑测试）。
- **改错判题**：每章至少 2 道；错误类型覆盖"断链 / 少 delete / 边界差一 / 指针未初始化"。
- **内存视图**：支持顺序表、单链表、栈三种；点代码行能看到对应内存变化。

## 六、技术上怎么落地（不动现有架构）

现有的"内容即数据"设计正好适合加这些东西，**不需要重写**：

### 6.1 内容 JSON 增加可选字段

```jsonc
// templates.json
{
  "id": "chain",
  "syntaxPoints": ["template", "pointer", "arrow", "new-delete"],   // 新增
  "cEquiv": "code/chain.c",                                         // 新增：C 版对照
  "lineNotes": [                                                    // 新增：逐行注释
    {"line": 12, "what": "定义一个类模板", "syntax": "template", "c": "typedef struct ..."}
  ]
}
```

### 6.2 新增一种题型：`fill`（挖空）

```jsonc
// problems/ll-08-fill.json
{
  "id": "ll-08-fill",
  "type": "fill",
  "baseCode": "code/array-list.cpp",     // 复用模板
  "blanks": [
    {"line": 42, "answer": "listSize - 1", "hint": "从最后一个元素开始"},
    {"line": 43, "answer": ">= theIndex",  "hint": "循环条件"}
  ]
}
```

后端拿到 `baseCode` + 用户填的空，**拼成完整程序**再走现有 `judge_submission`。
这样"填空"和"完整题"用的是同一套判题、同一套测试数据、同一套错误提示——工作量很小。

### 6.3 新增前端组件（不碰路由和状态管理）

```
components/cpp/CppGuide.vue        C++ 路标（12 个微课）
components/cpp/LineExplain.vue     逐行拆解（挂在 CodeViewer 上）
components/cpp/CCompare.vue        C / C++ 双栏对照
components/TermCompass.vue         术语罗盘
components/FillEditor.vue          填空编辑器（挖空处是输入框）
```

### 6.4 需要后端改的地方（很少）

1. 内容加载：`templates.json` 读取新字段（`syntaxPoints`、`cEquiv`、`lineNotes`）；
2. 判题路由：支持 `type: "fill"` 的请求（拼代码 → 调现有 judge）；
3. 静态检查：把"编译错误 → C++ 概念缺口"的映射从现在的 12 条扩到 25 条（例如 `no matching function` → "你可能不懂函数重载/默认参数"）。

## 八、我不想要的（避免又做成"泛泛的刷题网站"）

1. **不要更多"经典算法题"**。我现在需要的是读懂老师的代码，不是刷 LeetCode。
2. **不要一上来给完整答案**。填空/改错的价值在于"我自己补上那一行"，直接看答案等于没练。
3. **不要泛讲 C++**。什么 STL、继承、多态、智能指针，一律不碰，只讲数据结构代码里出现的。
4. **不要打乱课程顺序**。老师讲到队列就学队列，别让我去学红黑树。
5. **不要增加新的操作负担**。现在打开就能学，不要加签到、打卡、排行榜。

## 九、需要你确认的三件事

1. **C++ 急救包要不要做成"必须先过一遍"的前置？** 我倾向做成**可选但强提示**：第一次打开代码块时弹一次"要不要先看 3 分钟语法"，不强制。
2. **填空/改错题放在主线进度里，还是单独一个"练习场"？** 我倾向放在每题详情页里（同一道题有"完整版/填空版"两个入口），不额外增加目录层级。
3. **内存视图先做哪三种？** 我建议顺序表、单链表、栈。树和图的指针关系更复杂，等学到再说。
