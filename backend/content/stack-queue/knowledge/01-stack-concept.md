## 一个生活场景

食堂里摞起来的盘子：你只能从**最上面**拿，也只能往**最上面**放。最先放进去的盘子最后才能拿到——这就是**后进先出（LIFO, Last In First Out）**。

栈就是这样一个线性表：**只允许在一端（栈顶）进行插入和删除**。

```
        ┌─────┐
   top→ │  30 │   ← 栈顶，只能在这里进出
        ├─────┤
        │  20 │
        ├─────┤
        │  10 │   ← 栈底，动不了
        └─────┘
```

## 术语

- **入栈 / 压栈（push）**：插入元素，只能插在栈顶。
- **出栈 / 弹栈（pop）**：删除元素，只能删栈顶。
- **栈顶（top）**：允许操作的那一端。
- **栈底（bottom）**：不允许操作的那一端，固定不动。
- **空栈**：没有任何元素。

## 基本操作

```
InitStack(&S)     初始化空栈
StackEmpty(S)     判空
StackLength(S)    求元素个数
Push(&S, e)       入栈
Pop(&S, &e)       出栈并用 e 返回
GetTop(S, &e)     只读栈顶，不删除
DestroyStack(&S)  销毁
```

:::exam 一句话区分
`Pop` 会**删掉**栈顶，`GetTop` 只是**看一眼**。考试问"读取栈顶元素但不删除"就是在考这两个函数的区别。
:::

## 两种 top 约定（重点，容易混）

顺序栈用数组加一个 `top` 变量实现。但 `top` 到底指向哪儿，课本有两种写法，**考试会明确给其中一种**：

| | 约定 A：top 指向**栈顶元素** | 约定 B：top 指向**栈顶的下一个空位** |
| --- | --- | --- |
| 初始值 | `top = -1` | `top = 0` |
| 入栈 | `S[++top] = e` | `S[top++] = e` |
| 出栈 | `e = S[top--]` | `e = S[--top]` |
| 取栈顶 | `e = S[top]` | `e = S[top-1]` |
| 空栈判断 | `top == -1` | `top == 0` |
| 满栈判断 | `top == MAXSIZE - 1` | `top == MAXSIZE` |
| 元素个数 | `top + 1` | `top` |

**做题前先看清题目用的是哪种约定**，然后所有公式都跟着它走。混着用必错。

:::tip 记忆技巧
约定 B 的 `top` 其实就是"下一个要放东西的位置"，也就是**元素个数**。所以判空是 `top == 0`，个数就是 `top`，非常直观。约定 A 更贴近数组下标，写起来 `++top` / `top--` 对称。
:::

## 为什么栈这么重要

栈不只是考试题，它在真实程序里无处不在：

| 场景 | 栈的作用 |
| --- | --- |
| 函数调用 | 每次调用压一个栈帧，返回时弹出。这就是"调用栈" |
| 编译器的括号检查 | 遇到左括号压栈，右括号弹栈 |
| 表达式求值 | 中缀转后缀、后缀求值都靠栈 |
| 撤销功能 Ctrl+Z | 把操作压栈，撤销就弹栈 |
| 深度优先搜索 DFS | 用栈模拟递归 |
| 浏览器的后退 | 历史记录就是一个栈 |

**记住一句话：只要问题有"最近发生的事情要先处理"这个特征，就该想到栈。**
