## 排队打饭

队列和栈刚好相反：**在一端插入（队尾），在另一端删除（队头）**。先来的先走——**先进先出（FIFO, First In First Out）**。

```
 出队 ← [10] [20] [30] [40] ← 入队
        front           rear
```

- **队头（front）**：允许删除的一端。
- **队尾（rear）**：允许插入的一端。
- 空队列：`front == rear`（两个指针指向同一位置）。

## 基本操作

```
InitQueue(&Q)
QueueEmpty(Q)
EnQueue(&Q, e)     入队（只在队尾）
DeQueue(&Q, &e)    出队（只在队头）
GetHead(Q, &e)     读队头但不删除
QueueLength(Q)
```

## 顺序队列的"假溢出"（必考）

用数组实现队列，`front` 和 `rear` 都是下标：

```cpp
typedef struct {
    int data[MAXSIZE];
    int front, rear;   // rear 指向队尾元素的下一个位置
} SqQueue;
```

初始 `front = rear = 0`。入队 `data[rear++] = e`，出队 `front++`。

问题来了：

```
数组容量 6： [ ][ ][ ][30][40][50]
                        ↑     ↑
                     front   rear = 6（已经到数组末尾）
```

此时 `rear` 到了 6，明明前面还有 3 个空位（下标 0~2），却**不能再入队**了。这种现象叫**假溢出**——不是真的没空间，而是 rear 走到了尽头。

**解决办法：把数组看成环，用取模让 rear 绕回去**。这就是循环队列。

:::exam 三个必答
1. 什么是假溢出？→ 顺序队列中 rear 到达数组末尾，但数组前面还有空位，无法继续入队。
2. 为什么会产生？→ 出队只移动 front，前面的空间再也用不到，rear 单调递增。
3. 怎么解决？→ 循环队列（取模），或者每次出队整体前移（O(n)，不可取），或者用链队列。
:::

## 队列的典型应用

| 场景 | 为什么用队列 |
| --- | --- |
| BFS 广度优先搜索 | 要按"距离由近到远"的顺序访问 |
| 操作系统的任务调度 | 先来的先执行（FIFO 调度） |
| 打印机任务队列 | 多份文档按提交顺序打印 |
| 消息队列 | 生产者消费者解耦 |
| 滑动窗口最大值 | 单调队列，队头永远是最值 |
| 树的层次遍历 | 一层一层处理 |

一句话：**只要问题要求"按到达顺序处理"，就该想到队列。**
