## 三步法

分析一段代码的时间复杂度，固定走这三步：

1. **找基本语句**：执行次数最多的那条（通常是循环体里最内层的那句）。
2. **数它执行了多少次**（用 n 表示）。
3. **只留最高阶，去掉系数**。

## 单层循环

```cpp
int sum = 0;
for (int i = 0; i < n; i++) {
    sum += a[i];        // 执行 n 次
}
```

基本语句执行 n 次 → `O(n)`。

```cpp
for (int i = 0; i < n; i += 2) {   // 执行 n/2 次
    ...
}
```

`n/2` → 去掉系数 → 还是 `O(n)`。

```cpp
for (int i = 0; i < 100; i++) {    // 循环次数是常数
    ...
}
```

不管常数多大，都记作 `O(1)`。

## 双层循环：看内层循环的上界

**关键：内层循环跑了多少次，取决于它和外层变量的关系。**

### 情形一：内层与外层无关（乘法）

```cpp
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        c[i][j] = a[i] + b[j];   // 执行 n × n 次
    }
}
```

`O(n²)`。

### 情形二：内层从外层开始（求和，仍是平方级）

```cpp
for (int i = 0; i < n; i++) {
    for (int j = i; j < n; j++) {
        ...                       // 执行 n + (n-1) + ... + 1 = n(n+1)/2 次
    }
}
```

`n(n+1)/2` → 最高阶是 `n²` → `O(n²)`。**不能因为"内层不是每次都跑满 n 次"就以为是 O(n)**，这是最常见的错误。

### 情形三：内层按倍数增长（对数）

```cpp
for (int i = 1; i < n; i *= 2) {   // i = 1, 2, 4, 8, ...
    ...
}
```

执行 `log₂n` 次 → `O(log n)`。

```cpp
for (int i = 1; i <= n; i++) {
    for (int j = 1; j <= n; j *= 2) {
        ...                       // 外层 n 次，内层 log n 次
    }
}
```

`O(n log n)`。

## 两条运算规则

### 加法规则（顺序执行）

```cpp
for (i = 0; i < n; i++) x++;          // O(n)
for (j = 0; j < n*n; j++) y++;        // O(n²)
```

两段是**先后执行**，总时间是两者之和，取大的那个：`O(n) + O(n²) = O(n²)`。

### 乘法规则（嵌套执行）

```cpp
for (i = 0; i < n; i++)        // 外层 n 次
    for (j = 0; j < m; j++)    // 内层 m 次
        ...
```

总次数 `n × m` → `O(nm)`。当 m 也等于 n 时就是 `O(n²)`。

:::exam 一句话
**顺序结构相加取最大，嵌套结构相乘。**
:::

## while 循环：看它什么时候退出

```cpp
int i = 0;
while (i < n) i *= 2;     // 0 → 0，死循环！
```

注意这个反例：`i` 从 0 开始乘 2 永远是 0，所以是死循环。正确写法是从 1 开始。

```cpp
int i = 1, cnt = 0;
while (i < n) { i *= 2; cnt++; }   // cnt = ⌈log₂n⌉
```

→ `O(log n)`。

```cpp
int n = 1000;
while (n > 1) n /= 2;    // 折半，log 次
```

→ `O(log n)`。

## 递归的复杂度

递归的复杂度 = **递归调用的总次数 × 每次调用的工作量**。用递推式（又叫递归方程）表示。

### 情形一：每次只缩小一点点

```cpp
int f(int n) {
    if (n <= 1) return 1;
    return f(n - 1) + 1;     // T(n) = T(n-1) + O(1)
}
```

展开：`T(n) = T(n-1) + 1 = T(n-2) + 2 = ... = T(1) + (n-1)` → `O(n)`。

### 情形二：每次折半，只走一边

```cpp
int f(int n) {
    if (n <= 1) return 1;
    return f(n / 2) + 1;     // T(n) = T(n/2) + O(1)
}
```

要折半 `log₂n` 次才能到 1 → `O(log n)`。这就是**二分查找**的复杂度来源。

### 情形三：每次折半，两边都走

```cpp
void f(int l, int r) {
    if (l >= r) return;
    int mid = (l + r) / 2;
    f(l, mid);               // T(n) = 2T(n/2) + O(n)
    f(mid + 1, r);
    merge(l, r);             // 合并需要 O(n)
}
```

这是**归并排序**。结果 `O(n log n)`。

怎么记住？看递推式 `T(n) = 2T(n/2) + n`：

- 展开一层：`2T(n/2) + n`
- 展开两层：`4T(n/4) + 2n`
- 展开 k 层：`2ᵏ T(n/2ᵏ) + kn`
- 当 `n/2ᵏ = 1`，即 `k = log₂n` 时结束：`n·T(1) + n log n = O(n log n)`

**树形展开法**比背公式靠谱：把每层的总代价写出来，层数 × 每层代价。

### 情形四：没优化的斐波那契（反面教材）

```cpp
int fib(int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);   // T(n) = T(n-1) + T(n-2) + O(1)
}
```

调用次数呈指数增长 → `O(2ⁿ)`。n = 50 就要算几十亿次，这就是为什么必须改成递推或记忆化（`O(n)`）。

:::pitfall 最常见的四个错误
1. **看到两层循环就写 O(n²)，没看内层边界**（如果内层是 `j *= 2`，那是 O(n log n)）。
2. **把 `T(n) = 2T(n/2) + n` 算成 O(n)**，漏掉了 log。
3. **忘记递归的空间开销**（下一节讲）。
4. **循环里调用了 O(n) 的函数却只算了一层**，比如 `for(i<n) sort(a, n)` 是 `O(n² log n)`。
:::

## 几个必须记住的结论

| 算法 | 最好 | 平均 | 最坏 | 稳定性 |
| --- | --- | --- | --- | --- |
| 顺序查找 | `O(1)` | `O(n)` | `O(n)` | — |
| 二分查找 | `O(1)` | `O(log n)` | `O(log n)` | — |
| 冒泡排序 | `O(n)` | `O(n²)` | `O(n²)` | 稳定 |
| 快速排序 | `O(n log n)` | `O(n log n)` | `O(n²)` | 不稳定 |
| 归并排序 | `O(n log n)` | `O(n log n)` | `O(n log n)` | 稳定 |
| 堆排序 | `O(n log n)` | `O(n log n)` | `O(n log n)` | 不稳定 |

:::exam 重点
**快速排序的最坏情况是 `O(n²)`**——当每次选的主元都是最大或最小值时（比如对已有序数组取第一个元素当主元）。这几乎是每年必考的一道选择题。
:::

## 一个小练习（自己推）

```cpp
int i = 1, s = 0;
while (i <= n) {
    for (int j = 1; j <= i; j++) s += j;
    i *= 2;
}
```

外层 `i` 取 1, 2, 4, …, 共 `log₂n + 1` 次；第 k 次内层跑 `2ᵏ` 次。总次数是等比数列 `1 + 2 + 4 + ... + n ≈ 2n`。

所以是 **O(n)**，不是 O(n log n)——因为内层的规模在翻倍增长，总和被最后一项主导。这种题考试很爱出。
