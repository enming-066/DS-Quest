## 先把词分清楚

**数据**：所有能输入计算机并被处理的符号。数字、文字、图片都算。

**数据元素**：数据的基本单位，通常作为一个整体来处理。比如一条学生记录。

**数据项**：组成数据元素的、不可再分的最小单位。比如学生记录里的"学号""姓名"。

```
数据  ⊃  数据元素  ⊃  数据项
       （一条记录）  （学号）
```

:::exam 选择题高频
"数据项是不可分割的最小单位"——这句话是对的。
"数据元素是最小单位"——错，那叫数据项。

**数据对象**：性质相同的数据元素的集合，是数据的一个子集。比如"全体学生"。
:::

## 数据结构 = 逻辑结构 + 存储结构 + 运算

同一个逻辑结构，可以用不同的方式存到内存里，然后提供同一组操作。这三件事合起来才叫"数据结构"。

### 一看关系：逻辑结构（4 类）

| 逻辑结构 | 元素之间的关系 | 典型例子 |
| --- | --- | --- |
| **集合** | 除了"同属一个集合"，没有别的关系 | 一堆无序的整数 |
| **线性结构** | 一对一，除首尾外每个元素都有唯一前驱和后继 | 线性表、栈、队列、串 |
| **树形结构** | 一对多，每个元素最多一个前驱、可有多个后继 | 二叉树、哈夫曼树 |
| **图形结构** | 多对多，前驱后继都可能有多个 | 社交网络、地铁线路图 |

记忆抓手：**看"一个元素能连几个"**——0 个关系是集合，1 对 1 是线性，1 对多是树，多对多是图。

### 二看摆放：存储结构（4 类）

| 存储结构 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **顺序存储** | 用连续的存储单元，靠物理位置相邻表示逻辑相邻 | 随机访问 O(1)，密度高 | 插入删除要挪元素，容量固定 |
| **链式存储** | 用任意位置的结点，靠指针表示逻辑相邻 | 插入删除只改指针 | 不能随机访问，多一个指针开销 |
| **索引存储** | 额外建一张索引表（关键字 → 地址） | 查找快 | 索引表占空间，维护成本高 |
| **散列存储** | 用哈希函数直接算出地址 | 查找接近 O(1) | 有冲突要处理，不支持范围查询 |

:::tip 一句话区分
**逻辑结构是"想"出来的关系，存储结构是"放"进去的方式。**
考试问"线性表是逻辑结构还是存储结构"——答**逻辑结构**，它的存储实现是顺序表和链表。
:::

## 抽象数据类型（ADT）

ADT 定义"能做什么"，不定义"怎么做"。

```
ADT 三元组 {
    数据对象：D = { e1, e2, e3 | ei 是实数 }
    数据关系：R = { <e1,e2>, <e2,e3> }
    基本操作：
        InitTriplet(&T, v1, v2, v3)
        DestroyTriplet(&T)
        Get(T, i, &e)
        Put(&T, i, e)
        Max(T, &e)
} ADT 三元组
```

它的价值在于**封装**：使用者只需要知道有哪些操作，不需要知道内部用数组还是链表实现。C++ 的 `class`、Java 的 `interface` 都是在实现 ADT 的思想。

## 顺带记住：数据类型

- **原子类型**：值不可再分，如 `int`、`char`。
- **结构类型**：值由若干成分组成，如 `struct`。
- **抽象数据类型**：程序员自己定义的数据模型 + 一组操作。

## 这一章为什么重要

后面每一章都会重复同一套叙事：

1. 这个结构**逻辑上**是什么关系？（线性 / 树 / 图）
2. 它**在内存里**怎么存？（顺序 / 链式）
3. 各种操作**代价**多大？（复杂度）

把这三个问题问顺了，数据结构就学通了一半。
