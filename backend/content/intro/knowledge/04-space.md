## 空间复杂度在算什么

`S(n) = O(f(n))`：算法**额外**占用的存储空间随数据规模增长的趋势。

注意"额外"两个字：**输入数据本身占的空间不算**。比如对一个长度为 n 的数组排序，那个数组不算进空间复杂度；你在排序过程中又开了一个长度为 n 的辅助数组，这 n 就算。

常见量级：

| 空间复杂度 | 什么情况 |
| --- | --- |
| `O(1)` | 只用几个变量、几个指针（原地算法） |
| `O(log n)` | 递归深度是 log n（如二分的递归实现） |
| `O(n)` | 开了一个和 n 等大的数组、递归深度是 n |
| `O(n²)` | 开了二维数组 `int a[n][n]` |

## 递归的空间开销（必考）

递归不会凭空执行，每一层调用都要在**函数调用栈**上保存参数、局部变量、返回地址。所以：

```
递归的空间复杂度 = 递归深度 × 每层占用的空间
```

- 二分查找（递归版）：深度 `log₂n` → 空间 `O(log n)`
- 链表遍历（递归版）：深度 n → 空间 `O(n)`
- 快速排序（递归版）：平均深度 `log n` → 空间 `O(log n)`；最坏（每次只分出 1 和 n-1）深度 n → 空间 `O(n)`

:::exam 一句话
**"递归算法的时间复杂度看调用总次数，空间复杂度看最大递归深度。"**
这两个数字经常不一样，是简答题的经典陷阱。
:::

## 原地算法（in-place）

**原地**：只用 `O(1)` 的额外空间，直接在原数据上操作。

- 冒泡排序、选择排序、插入排序、堆排序：原地
- 快速排序：原地（只用了递归栈，数据本身没额外复制）
- 归并排序：**不是**原地，需要 `O(n)` 的辅助数组
- 单链表就地逆置：原地（只改指针）

所以"归并排序比快排稳定，但快排更省空间"这个说法是对的。

## 时间与空间的权衡

同一个问题，往往可以用空间换时间，或者反过来：

| 问题 | 时间优先 | 空间优先 |
| --- | --- | --- |
| 斐波那契第 n 项 | 递推 + 两个变量，`O(n)` 时间 `O(1)` 空间 | 记忆化，`O(n)` 时间 `O(n)` 空间 |
| 判断重复元素 | 哈希表，`O(n)` 时间 `O(n)` 空间 | 排序后比较，`O(n log n)` 时间 `O(1)` 空间 |
| 子段和查询 | 前缀和，`O(1)` 查询 `O(n)` 空间 | 每次暴力算，`O(n)` 查询 `O(1)` 空间 |
| 素数判断（多组） | 预处理筛表，`O(n)` 空间 | 每组试除，`O(1)` 空间 |

:::tip 实际怎么选
机考时优先保证**时间**——超时是硬性失败，内存超了也只是开了太大的数组而已。但要注意：`int a[100000000]` 是 400MB，直接 MLE，这种"为了快而乱开数组"的写法反而会挂。
:::
