## 算法 vs 程序

**算法**：对特定问题求解步骤的描述，是指令的有限序列。
**程序**：算法 + 数据结构 + 程序设计语言。

一句话：**算法是思路，程序是思路的落地。** 同一个算法可以用 C、Python、Java 写；同一个程序里也可能包含多个算法。

## 五个特性（必背）

| 特性 | 含义 | 反例 |
| --- | --- | --- |
| **有穷性** | 有限步之后结束，每一步都在有限时间内完成 | `while(1){}` 不是算法 |
| **确定性** | 每条指令含义明确、无二义，相同的输入必得相同的输出 | "把较大的数放到合适的位置"不算 |
| **可行性** | 每一步都能通过已实现的基本运算执行有限次完成 | "求 π 的最后一位"不可行 |
| **输入** | 有零个或多个输入 | 可以没有输入（如打印一行字） |
| **输出** | 有一个或多个输出 | 没有输出的计算没有意义 |

:::exam 最容易考的两个
1. **"算法可以没有输入，但必须有输出"** —— 对。
2. **"程序一定满足有穷性"** —— 错。程序可以死循环常驻（操作系统、服务器），那不是算法。
:::

## 好算法的四个目标

- **正确性**：能解决问题，这是底线。
- **可读性**：别人能看懂，自己三个月后也能看懂。
- **健壮性**：非法输入不会让它崩。
- **高效率与低存储**：这就是复杂度要解决的事。

## 四个渐近符号（课件第 2 章的重点，必考）

课件里不是只讲 O，而是讲了四个符号。判断"谁是上界、谁是下界"的选择题每年都有。

### ① 大 Ο：上界

若存在正常数 `c` 和 `n0`，使得当 `n ≥ n0` 时恒有 `f(n) ≤ c·g(n)`，则 `f(n) = O(g(n))`。

**记住：O 是上界，就像"≤"。** 所以 `3n+3 = O(n²)` 也是成立的（虽然很松）。

### ② 大 Ω：下界

若存在正常数 `c` 和 `n0`，使得当 `n ≥ n0` 时恒有 `f(n) ≥ c·g(n)`，则 `f(n) = Ω(g(n))`。

**Ω 是下界，就像"≥"。** `3n+2 = Ω(n)`、`3n+2 = Ω(1)` 都成立。

### ③ 大 Θ：同阶

`f(n) = Θ(g(n))` 当且仅当 `f(n) = O(g(n))` 且 `f(n) = Ω(g(n))`。

**Θ 是"同阶"，就像"="。** 这是最精确的描述：`3n+2 = Θ(n)`、`10n²+4n+2 = Θ(n²)`。

### ④ 小 ο：严格上界

`f(n) = o(g(n))` 当且仅当 `f(n) = O(g(n))` 且 `f(n) ≠ Ω(g(n))`。

**小 o 是"严格小于"，就像"<"。** `3n+2 = o(n²)` 成立，但 `3n+2 = o(n)` 不成立（它们是同阶）。

:::exam 一张表记住四个符号
| 符号 | 类比 | 含义 | 例子 |
| --- | --- | --- | --- |
| `O` | ≤ | 上界（不要求紧） | `3n+2 = O(n)`、`3n+2 = O(n²)` |
| `Ω` | ≥ | 下界（不要求紧） | `3n+2 = Ω(n)`、`3n+2 = Ω(1)` |
| `Θ` | = | 上下界同阶 | `3n+2 = Θ(n)` |
| `o` | < | 严格上界（不同阶） | `3n+2 = o(n²)` |

**三个多项式定理**（课件原话）：若 `f(n) = aₘnᵐ + … + a₁n + a₀` 且 `aₘ > 0`，则
`f(n) = O(nᵐ)`、`f(n) = Ω(nᵐ)`、`f(n) = Θ(nᵐ)` 同时成立。
:::

:::pitfall 考试里的两个陷阱
1. **"错误界限"**：`3n+2 = O(1)` 是**错**的。反证：若存在 c、n0 使 `3n+2 ≤ c` 对一切 n ≥ n0 成立，则 n 增大时左边无界，矛盾。
2. **"松散界限"**：`3n+3 = O(n²)` 是**对**的，只是不是最小上界。题目问"下列哪个不成立"时要小心这种"成立但很松"的选项。
:::

### 对数为什么不用写底

```
log_a n = log_b n / log_b a
```

换底只差一个常数倍，而复杂度忽略常数，所以 `O(log₂n)`、`O(log₁₀n)`、`O(ln n)` 都写成 `O(log n)`。

## 常见复杂度阶（从小到大）

| 阶 | 名称 | n = 10 | n = 100 | n = 1000 | 典型来源 |
| --- | --- | --- | --- | --- | --- |
| `O(1)` | 常数 | 1 | 1 | 1 | 数组按下标取值、哈希查找 |
| `O(log n)` | 对数 | 3.3 | 6.6 | 10 | 二分查找、平衡树查找 |
| `O(n)` | 线性 | 10 | 100 | 1000 | 一次遍历、线性表求最大值 |
| `O(n log n)` | 线性对数 | 33 | 664 | 9966 | 归并排序、快排平均 |
| `O(n²)` | 平方 | 100 | 1e4 | 1e6 | 冒泡 / 选择 / 插入排序、双重循环 |
| `O(n³)` | 立方 | 1000 | 1e6 | 1e9 | 三重循环、Floyd |
| `O(2ⁿ)` | 指数 | 1024 | 1e30 | 天文 | 未优化的递归斐波那契 |
| `O(n!)` | 阶乘 | 3.6e6 | 巨大 | 巨大 | 全排列、旅行商暴力 |

**必须背下来的大小关系**：

```
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)
```

## 数据规模反推复杂度（做题的第一反应）

| n 的范围 | 能过的复杂度 | 说明 |
| --- | --- | --- |
| n ≤ 10 | `O(n!)`、`O(2ⁿ)` | 暴力搜索、全排列 |
| n ≤ 20 | `O(2ⁿ)` | 状压 DP |
| n ≤ 500 | `O(n³)` | Floyd、三重循环 |
| n ≤ 5000 | `O(n²)` | 冒泡、二维 DP |
| n ≤ 1e6 | `O(n log n)`、`O(n)` | 排序、双指针、前缀和 |
| n ≤ 1e8 | `O(n)` | 只能扫一遍，常数还要小 |
| n ≤ 1e18 | `O(log n)`、`O(1)` | 二分、快速幂、数学公式 |

1 秒大约能做 **1e8 次**简单运算（C++ 在普通电脑上）。所以看到 `n = 1e5` 就要警惕 `O(n²)`，看到 `n = 1e7` 就基本只能 `O(n)` 了。

:::exam 这一张表是机考的命根子
题目给的范围不是随便写的，它就是在暗示你该用什么算法。
`n ≤ 1e5` + 要排序 → `O(n log n)` 一定够；你写 `O(n²)` 直接 TLE。
:::

## 最好、最坏、平均

同一个算法，不同输入下代价可能差别很大。

以"在顺序表里查找 x"为例：

- **最好情况**：x 就在第一个，比较 1 次 → `O(1)`
- **最坏情况**：x 在最后或不存在，比较 n 次 → `O(n)`
- **平均情况**：假设每个位置等概率，平均比较 `(n+1)/2` 次 → `O(n)`

考试不给限定时，默认问**最坏情况**；但如果它问"平均时间复杂度"，一定要答平均。

栈和队列的 push/pop 是 `O(1)`，而顺序表的插入删除是 `O(n)`——差别就在这里：前者只在端点操作，后者要挪元素。
