## 为什么它能比 O(n log n) 快

比较排序（冒泡、快排、归并）有一个理论下界：`Ω(n log n)`。
箱子排序**根本不比较**，它利用了"关键字是 [0, range] 里的小整数"这个额外信息，直接把结点放进对应的箱子。

代价是：**必须知道关键字范围，而且范围不能太大**。100 万个数据、关键字是 0~1e9，就不能用。

## 过程（课件 P58~P63）

假设有 5 个结点，关键字分别是 `2, 1, 2, 0, 1`，range = 2，开 3 个箱子：

```
① 分发（按关键字挂到对应箱子的【尾部】）
   箱0: (0,id4)
   箱1: (1,id2) → (1,id5)
   箱2: (2,id1) → (2,id3)

② 收集（按箱号从小到大串起来）
   (0,id4) → (1,id2) → (1,id5) → (2,id1) → (2,id3)
```

收集完就是有序的，整个过程没有比较过任何两个关键字。

## 为什么是稳定的

分发时，同一个箱子里的结点是**按原顺序**挂到尾部（`top[b]->next = p`）。收集时又按箱号顺序接。
所以相同关键字的结点，**谁先进箱子谁就排在前面**——这就是稳定。

如果把"挂尾部"改成"插头部"（像头插法），相同关键字就会倒序，排序变成不稳定的。
这是考试里问"箱子排序如何实现稳定"的标准答案。

## 复杂度

| 步骤 | 代价 |
| --- | --- |
| 分发 | 每个结点一次，`Θ(n)` |
| 收集 | 扫一遍所有箱子，`Θ(range)` |
| **合计** | **`Θ(n + range)`** |

空间：箱子数组 `Θ(range)`，另外每个结点一个指针（本来就有）。

当 `range` 和 n 差不多时，就是线性的——比 `O(n log n)` 还快。

## 课件里的两种写法

1. **朴素版**：用 `Chain` 类型的数组当箱子，每个结点调用 `bin[b].insert(...)`。
   缺点：`insert` 内部要走到表尾，最坏会退化。
2. **优化版**（本页代码）：直接用 `bottom[]` / `top[]` 两个指针数组记住每个箱子的头和尾，
   分发时 `Θ(1)` 挂到尾部。

课件把第二种写成 `Chain<T>::BinSort` 的成员函数，就是为了能直接操作 `firstNode` 和 `next`，避免封装带来的开销。

:::exam 三个常考点
1. 复杂度 `Θ(n + range)`，不是 `Θ(n)`——千万别漏掉 range。
2. 稳定的原因：**分发时挂到箱子尾部**。
3. 适用条件：关键字是**范围较小的整数**；范围远大于 n 时反而浪费空间和时间。
:::

:::pitfall 两个常见错误
- 收集时忘记把最后一个箱子的尾结点 `next` 置空，链表会出现脏指针。
- 分发时没有把结点从原链表摘下（`p->next = 0`），导致新旧链互相纠缠。
:::
